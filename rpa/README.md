本机罗盘采集器

网站入口：<http://127.0.0.1:8765/#business>。在“经营数据”中连接账号，完成独立 Chrome 窗口里的罗盘登录。默认每分钟同步，页面可设置 30 秒至 10 分钟。关闭罗盘窗口会暂停该账号；在页面点击“开启同步”或“打开罗盘 / 登录”可恢复。

本地功能包括账号登录、今日场次发现、直播状态、核心指标、商品列表、采样趋势、部分失败提示、暂停/恢复、按场次导出 JSON。每轮优先同步最多 3 个今日场次。采集使用固定的只读网页请求，不加载外部下发的脚本，也不依赖外部调度或上报服务。

历史场次目录可选择上海时区近 90 天内的起止日期，每次读取罗盘目录的 10 场并在本机筛选。读取进度绑定账号 UID、日期和固定查询窗口；更换范围须从第 1 页重读。日期无法判定的场次会计数提示，不会偷偷导入。最多读取 50 页，达到上限时结果可能不完整。目录导入与历史报表读取不会写入飞书；真实有数据账号验收仍待完成。

已保存的结束场次可按所选日期批量读取三类历史报表。启动后后台逐接口、逐场读取，网页立即返回并显示进度；一个账号同一时间只能运行一个读取任务。每场完成后保存报表和游标，重复运行会跳过已有完整报表，部分报表可在新任务中重试。暂停、限流、账号切换会停止后续请求；限流至少等待五分钟，重启后任务保持暂停，必须由用户手动继续。批量任务仍只写本机历史报表，不生成实时快照或飞书待写记录。此流程通过合成测试，未在真实罗盘有数据账号上验收。

同一数据目录仅允许一个采集进程；实时同步、历史目录、单场详情或回填遇到限流时，账号记录五分钟退避时间，重启后新批次、历史读取和手动同步仍须等待。不同轮次部分成功的报表按接口保留最近成功结果，页面和复盘导出会注明沿用接口的原读取时间。

数据库和独立浏览器会话默认位于 Mac 的 `~/Library/Application Support/LiveOps/rpa/` 或 Windows 的 `%APPDATA%\LiveOps\rpa\`；可通过 `LIVEOPS_DATA_ROOT` 统一覆盖，`LIVEOPS_RPA_DATA` 可单独覆盖采集器目录。数据最多保留 30 天，每个场次最多 1000 次快照；图表读取最近 120 次。采集器只通过网站 Python 服务的私有标准输入/输出通信，不额外开放网络端口。

金额与比例保留原值及接口提供的单位，未取得的指标显示“—”。网页登录及接口格式会变化；请求失败、登录失效或结构无法识别时显示错误，保留已保存的历史快照。多人共享一台电脑时，数据对该操作系统用户可见。

运行环境为 macOS Apple Silicon 或 Windows 10/11 x64、Chrome 或 Edge（Mac 默认查找 Chrome）、Python 3.9+、Node.js 24+（使用内置 SQLite）、Playwright Core。在仓库根目录运行 `npm ci` 安装 Playwright Core；安装器也可安装独立组件。`rpa_bridge.py` 可通过 `LIVEOPS_NODE`、`LIVEOPS_PLAYWRIGHT_MODULE` 和 `LIVEOPS_CHROME` 指定其他安装。独立启动使用根目录的 `启动直播操盘台.command` 或 `启动直播操盘台.bat`。首次连接仍需在平台官方窗口登录或扫码，Windows 实机流程尚未验收。

飞书多维表格同步

“经营数据”下方的飞书卡片支持选择罗盘账号，将本机已保存的场次写入飞书多维表格。每个账号 UID + 直播间 ID 对应一条记录，后续采样更新该行；默认暂停，配置完成后点击“开启自动同步”。也可先绑定已创建的表格链接；尚未填写应用凭据时显示“表格已绑定 · 待授权”，不会发出飞书写入请求。保存或修改配置会暂停同步，检查连接后再开启。服务需持续运行；电脑睡眠、关机或采集器退出期间不采集也不上传。

设置步骤：
1. 在 <https://open.feishu.cn/app> 创建企业自建应用，申请并发布多维表格读写权限 `bitable:app`（也可使用数据表读取、字段读取/创建、记录检索/创建/更新的细分权限）。
2. 在目标多维表格右上角“…”→“添加文档应用”添加这个应用并授权。若启用高级权限，请授予应用可管理权限，以免记录查询被权限过滤。
3. 在工作台填写 `https://xxx.feishu.cn/base/…?table=tbl…` 链接，以及 App ID / App Secret，勾选需要同步的账号，保存并检查连接。当前不接受知识库 `/wiki/` 链接，应先打开原多维表格。
4. 检查成功后开启自动同步。首次同步会补齐标准文本字段，不改变其他字段；同名列类型不匹配会报错，请使用空数据表或将这些列设为文本类型。

写入账号、账号 ID、直播间 ID、标题、状态、采样时间、采集状态、8 项核心指标、指标原值 JSON、商品数量及商品明细 JSON。核心指标用显示值及原单位写入文本列，原始数字另保留在 JSON 中，不擅自转换金额或比例，长 ID 保持文本，缺失数据留空。实时逐次趋势仍保存在本机，飞书每行是该场最新快照；暂无场次时不会写测试行。单元格内容超过 95000 字符时明确报错，不截断商品列表。

使用飞书官方 API：`accounts.feishu.cn/oauth/v3/token` 获取应用令牌，`open.feishu.cn/open-apis/bitable/v1` 读写表格。密钥保存在本机 RPA 数据目录的 `data.sqlite`，不返回浏览器、不写日志、不写入飞书；本机当前系统用户可读取该文件。Mac 设置 0600 权限，Windows 依赖当前用户目录的访问控制。表格链接与 App ID 可在工作台查看，App Secret 留空表示保留已存密钥。

待写数据、创建幂等 token 与成功检查点使用同一个 SQLite 数据库保存。网络异常后先查询稳定同步键再重试创建/更新，创建请求复用持久化 UUID，按 30 秒至 10 分钟退避，重启后继续；查到多个同步键时报告冲突，不删除用户行。暂停后已发出的单次请求可能完成，后续场次停止。尚未开始写入的场次上传最近保留的快照（本机保留 30 天）；已经开始但未确认成功的写入独立持久化，超过快照期限仍可恢复；未开启自动同步时可单次手动写入。

## 录屏压缩与原件清理

“运行设置 → 录屏后处理”可设置自动压缩和“压缩校验成功后删除原录屏”。本机当前已按用户要求开启自动压缩，并保存 `keepOriginal: false`；代码缺省保留原件，避免缺少设置时误删。

后处理实现在根目录 `media_pipeline.py`，每 30 秒扫描保存目录，等待文件至少 60 秒未修改且没有进程占用后处理。压缩完成后全片解码检查，检查通过且源文件没有发生变化才删除对应原件。压缩失败、校验失败或删除失败均保留原件并记录错误；已生成的压缩视频不参与再次压缩。同名但不同扩展名的源文件独立处理。工作台重启后仍可发现此前未处理的小文件与录屏。

压缩只依赖 FFmpeg。Whisper 和模型可用时，使用压缩视频生成 TXT / SRT；这些文本与字幕保留。压缩与转写状态分别显示。压缩结果名称为 `<原文件名>.compressed.mp4`，存放在原录屏旁，文本和字幕放在 LiveOps 的 transcripts 目录。

验证：`python3 -m unittest discover -s tests -p 'test_*.py' -v`。本机另用 3 秒带音轨的合成视频实测了 H.265 压缩、校验和原件删除，并验证损坏输入保留；真实直播录制器当前未连接，未启动新直播录制。


## 网页连接与管理录制器

“直播监控”顶部可点击“启动并连接”“检查连接”，并直接进入“录制器设置”。“运行设置”提供“启动并连接”“检查连接”“保存并应用设置”“停止录制器”。首次连接会将工作台已保存的直播间以暂停状态导入，需在账号详情点击“开启监测”后才会自动录制；后续启动保留用户选择的监测状态。

“保存并应用设置”先保存表单，成功后重启录制器并应用参数。正在录制时停止和重启按钮禁用，需先在直播监控中暂停相应账号。连接状态每 5 秒更新，不覆盖正在编辑的表单。设置可在录制器离线时保存。

本机进程管理由 `recorder_service.py` 实现，使用已安装 bililive-go 和 FFmpeg，仅开放本机回环接口；不会重复启动，也不会停止其他软件启动的录制器。录制参数与房间监测状态持久化在 LiveOps 的 plugin-settings 目录。网页启动器仍为根目录“启动直播操盘台.command”。
